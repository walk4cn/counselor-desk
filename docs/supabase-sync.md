# 云端同步（Supabase）

从 v4.5 起，辅导员工作台可以把 v8 工作区数据保存到 **自己的 Supabase 项目**，同一账号在 Windows 桌面端、网页端和不同设备上登录后即可互通。

同步是**可选的**：不配置时行为与之前完全一致（数据只保存在本机）。云端同步开启后，本机仍然保留一份完整镜像，登录失效或断网时可继续使用本地副本。

> 本文档面向使用者。开发说明见 [开发文档](development.md) 与 `src/core/cwb-supabase.js`。

## 一、工作方式

- 工作台把整套工作区（学生台账、谈话、党务、成绩、资料库、设置等）按 v8 持久化协议切成若干“记录”，写入 Supabase 的一张表。
- 每次保存时，最新记录会立刻上传；打开工作台时会自动从云端拉取最新数据。
- 多个终端以“最后保存者生效”为准，并保留最近 3 个世代用于校验和恢复。
- 数据按登录账号隔离（数据库行级安全 RLS），不同账号之间互相不可见。

## 二、一次性准备（约 5 分钟）

### 1. 创建 Supabase 项目

在 [supabase.com](https://supabase.com) 注册并创建一个免费项目（选择一个离你较近的地区，例如 ap-southeast-1 新加坡）。

### 2. 执行初始化脚本

1. 进入 Supabase 控制台 → **SQL Editor**（SQL 编辑器）。
2. 点击 **New query**（新建查询）。
3. 粘贴仓库中 `supabase/schema.sql` 的全部内容。
4. 点击 **Run**（运行）。

脚本会创建 `workspace_records` 表并开启行级安全策略，不修改其他任何结构。

### 3. 获取项目地址与 anon 公开密钥

进入控制台 → **Settings → API**（设置 → API）：

- **Project URL**：例如 `https://abcdefgh.supabase.co`
- **anon / public** 密钥：以 `eyJhbGciOi...` 开头的一串字符

anon 密钥是**公开**密钥，仅用于让客户端发起请求；真正限制访问的是数据库里的行级安全策略。

## 三、在每台设备上启用

1. 打开工作台 → 右上角 **设置** → **云端同步（Supabase）**。
2. 填写**项目地址**和 **anon 公开密钥**，点击 **保存配置**。
3. 在下方输入邮箱和密码，点击 **注册**（第一次使用）或 **登录**（已有账号）。
   - 若项目开启了邮件验证，注册后请先到邮箱完成验证再登录。
4. 点击 **立即同步**：
   - 云端还没有数据时，会把本机数据推送到云端；
   - 云端已有数据时，会拉取云端最新数据并应用到本机。

设置完成后，顶栏保存状态会显示“已保存 · 云端”，表示每次修改都会同时上传。

## 四、多终端互通流程

- **首次同步**：设备 A 完成上述设置并点击“立即同步”后，设备 B、C 登录同一账号，打开工作台时会自动拉取云端数据，无需手工操作。
- **日常使用**：任何一端的修改都会实时上传；另一端下次打开（或点击“立即同步”）即可看到。
- **换新设备**：新设备上只需重复“三、在每台设备上启用”的步骤，登录同一账号即可恢复全部数据。

## 五、注意事项与限制

- **附件（照片、文件）**：附件索引会随工作区同步，但**二进制内容仍保存在本机**（网页端为浏览器存储，桌面端为本地附件仓）。需要跨设备查看附件时，请使用[备份与迁移](v4-migration-and-backup.md)导出导入，或在目标设备上重新上传。
- **冲突处理**：两个终端同时修改同一份数据时，以最后保存的版本为准，系统保留最近世代以便校验与恢复。
- **隐私**：Supabase 项目是学校或你本人的云服务，学生数据会离开本机。请评估学校对敏感数据的存储要求，必要时使用自己的私有项目、启用邮件验证，并按需开启 Supabase 的备份功能。
- **离线**：断网时保存会进入“保存失败，待重试”，数据保留在本机；恢复网络后点击“重试保存”即可继续上传。
- **清空数据**：“设置 → 清空全部数据”只清空本机与当前账号的云端数据；其他账号的数据不受影响。

### 常见问题

**注册提示“注册请求过于频繁 / Email rate limit exceeded”**
这是 Supabase 对同一邮箱发送验证邮件的限流（默认约每小时 2 封），通常由短时间内重复点击“注册”引起。

- 先到收件箱和**垃圾邮件**里找找有没有收到验证邮件：收到了就直接点验证链接，然后回来**登录**即可，无需再注册。
- 若确实没收到，请等约 1 小时后重试一次即可。
- 提示“该邮箱已注册”时同理，直接登录即可。

**登录提示“邮箱尚未验证”**
说明注册邮件验证还没有完成。到邮箱点击验证链接；若链接失效，可在 Supabase 控制台 **Authentication → Users** 里找到该用户，点击“重新发送验证邮件”（Resend confirmation），或直接在该页面手动确认邮箱。

**想省去邮件验证（可选）**
在 Supabase 控制台 **Authentication → Providers → Email** 里关闭“Confirm email”选项，注册后将立即登录、无需验证邮件。注意关闭后任何人都可以用任意邮箱注册，请结合你的使用场景决定。

**注册成功后打开验证链接页面报错**
多数是因为项目没有配置回调地址：在控制台 **Authentication → URL Configuration** 里把 **Site URL** 填成你的部署地址（如 `https://你的域名`），保存后重新发送验证邮件即可。

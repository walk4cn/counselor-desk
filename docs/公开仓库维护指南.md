# 公开仓库维护指南

这份 How-to 指南面向维护者，说明如何在不破坏本地优先边界的前提下更新主页、源码和文档。

## 发布前准备

1. 从 `master` 创建带版本号的分支，确认工作区没有未解释的修改。
2. 使用脱敏样表复现网页端导入、编辑、附件、备份、恢复和导出闭环。
3. 使用真实浏览器和目标桌面平台完成安装、升级、异常退出和卸载测试。
4. 检查 `assets/` 中的图片、Logo、替代文本和素材来源记录。

## 主页更新顺序

1. 先改 `README.md` 的一句话定位和功能地图，再调整截图与链接。
2. 主页首屏只能保留一个视觉主角：`assets/counselor-desk-hero.png`；其余图片用于解释功能。
3. 新增 emoji 只作为信息分组，不替代按钮文字、表格列名或无障碍说明。
4. 若替换 Logo 或 favicon，必须同时检查 `assets/logo.svg`、`assets/app-icon.svg`、`index.html` 的 `<link rel="icon">` 和桌面端回退路径。
5. 在 `CHANGELOG.md` 记录面向用户的变化，在 `docs/品牌与素材说明.md` 记录视觉变化和素材来源。

## 文档同步表

| 变化 | 必须同步 |
| --- | --- |
| 新增功能或字段 | README 功能地图、使用手册、数据格式约定、CHANGELOG |
| 数据存储 / 迁移变化 | 架构与验收、平台构建矩阵、安全说明、桌面端说明 |
| 发布产物变化 | README 下载链接、验收报告、构建脚本和版本路线 |
| 主页视觉变化 | README、品牌与素材说明、截图替代文本 |

## 质量门禁

```bash
pnpm test
pnpm run lint
pnpm run check:public
pnpm run test:release
git diff --check
```

对外发布前再执行 `pnpm run build:package` 和桌面端平台构建，并把实际结果写入验收报告。任何“配置已存在但未在目标主机实测”的平台，都必须标为“待签收”。

## 安全边界

- 不把真实学生信息、数据库、附件或诊断包提交到公共仓库。
- 不在 Issue、截图和生成式图片中出现身份证号、手机号、家庭地址或可识别个人信息。
- 导出敏感字段前必须二次确认；删除、清空、恢复和卸载删除数据也必须二次确认。
- 生成诊断包时仅保留版本、平台、健康度、错误日志和脱敏统计，不自动上传。

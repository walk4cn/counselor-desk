# 平台构建矩阵

这是一份发布前的 How-to / Reference 文档，区分“源码已经准备好”和“当前主机已经实机签收”，避免把跨平台配置误写成已发布成品。

## 当前状态

| 平台 | 架构 | 源码配置 | 当前工作区实机签收 | 产物 |
| --- | --- | --- | --- | --- |
| Windows | x64 | ✅ | ✅ 已验证安装、启动、SQLite、迁移、卸载 | NSIS `.exe` |
| Windows | ARM64 | ✅ 预留 | ⏳ 需 ARM64 主机 | NSIS / portable |
| macOS | Intel | ✅ `electron-builder --mac` | ⏳ 需 macOS 主机 | DMG / ZIP |
| macOS | Apple Silicon | ✅ `electron-builder --mac` | ⏳ 需 macOS 主机 | DMG / ZIP |
| Linux | x64 | 🧭 预留 | — | AppImage / deb |
| 浏览器 | Chrome / Edge / Firefox / Safari | ✅ 单文件 HTML | Chrome / Edge 已回归，其余按发布清单签收 | `index.html` / 发布包 |

macOS 的 DMG / ZIP、代码签名和公证必须在 macOS 主机完成。Windows 机器可以检查配置和依赖，但不能替代 Apple 工具链的最终签收。

## Windows 构建

```powershell
cd desktop
npm install
npm run rebuild:native
npm run dist:win
```

构建完成后，回到仓库根目录执行：

```powershell
pnpm run test:desktop-electron
```

安装器验收必须覆盖：安装、启动、升级覆盖、卸载保留数据、卸载删除数据两条路径。

## macOS 构建

在 macOS 主机上：

```bash
cd desktop
npm install
npm run rebuild:native
npm run dist:mac
```

生产发布还需要在 `electron-builder.yml` 中配置签名身份与公证凭据。公开仓库只提交可复现配置，不提交证书、私钥或用户数据。

签收清单：

- Intel 与 Apple Silicon 均可安装、启动和退出；
- `better-sqlite3` 与附件目录加载正常；
- 旧 JSON / 便携 HTML 迁移报告可读；
- 关闭窗口前保存、异常恢复和备份恢复闭环通过；
- DMG / ZIP 在干净用户目录打开，卸载不误删数据；
- 产物已签名、公证（如用于对外分发），并记录 SHA-256。

## 浏览器与离线 HTML

浏览器端主写入源是 IndexedDB；初始化失败时进入明确标识的兼容模式，并提示用户先导出备份。直接用 `file://` 打开时，部分浏览器会限制模块或文件 API，发布演示优先使用 GitHub Pages 或本机静态服务器：

```bash
python -m http.server 4173
```

## 产物与文档同步

每次版本发布必须同时更新：`package.json`、`desktop/package.json`、`CHANGELOG.md`、README、使用手册、验收报告和本矩阵。发布包不得包含测试数据、临时文件、调试日志或未审计依赖。

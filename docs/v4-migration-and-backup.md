# 备份、迁移与恢复

备份不是“出问题以后再想办法”的按钮，而是导入、覆盖、换机和交接前的标准动作。本页只说明安全的通用做法；具体菜单名称和可用格式以当前 Release 为准。

## 什么时候必须先备份

- 批量导入一份新名单或覆盖已有数据前。
- 清理浏览器、重装系统、换电脑、换浏览器或升级桌面版前。
- 交接岗位、移动资料库或删除大批量附件前。
- 要把数据交给另一位授权同事前。

## 推荐的备份习惯

1. 在工作台内生成备份，使用独立且妥善保管的口令（若版本要求口令）。
2. 为备份命名或记录日期、用途和来源，例如“2026-08-13-开学前台账”。
3. 保存到受控位置，例如学校批准的加密介质或受控网络盘；不要放进公开群、个人社交平台或不明网盘。
4. 至少在另一台测试设备或测试浏览器中完成一次恢复验证，再依赖它用于换机或交接。

### 一个可执行的备份节奏

| 时机 | 建议动作 | 为什么 |
| --- | --- | --- |
| 大批量导入前 | 建立恢复点并导出完整备份 | 方便撤回映射错误、重复合并或字段判断错误。 |
| 每个重要节点后 | 导出一份带日期和用途的备份 | 避免把“期末前、评优前、交接前”的状态混在一起。 |
| 换设备前 | 在旧设备导出，在新设备恢复并抽查 | 复制浏览器目录或安装目录不能替代受支持的迁移。 |
| 岗位交接时 | 双方分别保留交接前快照与恢复验证记录 | 让责任边界、附件完整性和后续追溯更清楚。 |

## 网页、离线文件与桌面端的区别

| 使用方式 | 数据通常在哪 | 换设备时正确做法 |
| --- | --- | --- |
| 网页版 | 当前浏览器的本地存储 | 在旧环境导出备份，在新环境恢复。不要依赖浏览器同步。 |
| 离线 HTML | 当前浏览器或便携页面的本地空间 | 把备份与离线文件分开保存；不要只复制 HTML。 |
| 桌面端 | 当前系统用户的数据目录与附件库 | 升级前先导出备份；目标设备安装后再恢复并抽查附件。 |

## 恢复时的安全顺序

1. 先导出目标设备当前数据，作为恢复前快照。
2. 确认备份来源、版本、口令和共享范围。
3. 选择“合并”还是“覆盖”前先看差异说明；不确定时优先在测试环境演练。
4. 恢复完成后抽查学生记录、附件、谈话/任务及资料库，而不只看“恢复成功”提示。
5. 确认无误后再处理旧设备或旧备份。

### “合并”与“覆盖”怎么选

- **合并**适合目标设备已经产生新记录、只希望补进来源记录的情况。恢复后需要抽查同一学生、同一附件或同一业务记录是否出现重复。
- **覆盖**适合明确要回到某一份完整快照的情况。覆盖前先导出目标设备当前数据，因为这一步会改变当前工作区。
- 无论选择哪种方式，附件都应作为恢复后的必查项：随机打开几份记录，检查文件、缩略图和关联学生是否一致。

## 常见误区

- **只复制安装包**：安装包不等于业务数据。
- **只复制表格**：表格可能不包含附件、谈话、任务或资料库索引。
- **把备份当作普通附件转发**：备份可能包含完整学生信息，应按敏感文件处理。
- **在唯一数据上首次测试覆盖恢复**：先做快照，再用脱敏环境演练。

## 版本兼容

发布版本会在 Release 说明中列出可导入的历史格式、schema、加密备份和桌面数据兼容范围。当前 v4.4.2 延续 schema v8；请只使用 [正式 Release](https://github.com/7752777/counselor-desk/releases/tag/v4.4.2) 的程序或离线 HTML 处理正式数据，不要将开发分支构建用于生产迁移。

### v4.4 的迁移原则

v4.4 使用 schema v8 工作区。它的迁移目标是保留内部 ID、附件关联、历史学号、自定义字段和可以读取的历史记录；迁移前会建立恢复点。遇到无法判断的旧字段或冲突记录，系统应提示并保留原始信息供人工判断，而不是静默覆盖。正式兼容范围、加密格式和桌面迁移结果见 [v4.4.2 Release](https://github.com/7752777/counselor-desk/releases/tag/v4.4.2) 与 [发布验收记录](./v4-acceptance-report.md)。
